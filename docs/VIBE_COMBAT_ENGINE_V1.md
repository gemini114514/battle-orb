# Vibe Combat 三段式本地战斗引擎 V1

## 目标与边界

Vibe Combat 为《轮回战场》V3.2.6 专用。AI 负责理解意图、编排战术与润色叙事；命中、伤害、资源、状态、位置、死亡和战果只能由服务器本地规则引擎裁定。V1 使用单人界面，但所有命令均携带 `playerId`、`seatId`、`commandId` 与 `expectedVersion`，为多人控制权预留协议。

## 三段式流程

1. **正文 AI / 遭遇导演**：把剧情上下文整理成隐藏的 `EncounterDraft`，只描述地点、参战者、威胁和意图，不决定数值与胜负。
2. **战斗 AI / 计划编译器**：将自然语言策略和卡片能力编译为可审阅策略或沙箱脚本；服务器校验遭遇、补全数值，并以固定种子逐事件演算。
3. **正文 AI / 战报融合**：接收不可变 `BattleResultBundle`，输出紧凑连贯的最终剧情。服务器负责插入检定记录和 MVU Patch；叙事失败不回滚战果，也不重掷。

模型请求必须串行。单次等待/无数据超时为 300 秒；正文默认最大输出不少于 30000 Token。战斗循环内不调用模型。

## 权威会话

SQLite WAL 保存 `CombatSession`：战斗 ID、剧情存档 ID、规则版本、256 位种子、状态版本、事件序号、控制模式、控制席位、开战快照/哈希、区域图、个体与群组、轮次/行动游标、策略、接管条件、脚本及审批哈希、不可变事件账本、最终结果和 MVU Patch。

状态为 `draft / awaiting_script_approval / ready / running / paused / completed / abandoned / error`。所有写命令用 `commandId` 幂等；`expectedVersion` 不匹配返回 409，禁止重复结算。

## V3.2.6 核心规则

- D100：攻击为 `1d100 + 属性修正 + 位阶修正` 对防御 DC；优势取 2d100 高值，劣势取低值。
- 豁免 DC 默认 `50 + 施法者修正`。原始 96–100 为奇迹，1–5 为灾难。
- 每轮刷新状态、持续伤害/恢复与冷却，再按 `1d100 + 先攻DC` 排序行动。
- 行动经济：移动、主要、次要各一次；多目标倍率为 2/1.5、3/2、4/2.5、5+/3，主目标 100%、次目标 70%，范围技能各目标 100%。
- 弱点在减伤前 ×1.5；物理/魔法/真实伤害分轨；THP 先于 HP；倒地后再次受伤死亡。
- 形态共享本体 HP/EP；召唤物独立；载具使用完整度/能源。
- 普通同模板敌人以 cohort 批处理但保留每个稳定 ID、HP、状态、位置与击杀归属；Boss、精英、命名单位永不合并。

## 空间、群战与敌方策略

地图使用区域图和接触/近/中/远距离带。区域具有邻接、阻挡、视线、掩体、高差、危险与容量。开放区域默认最多 6 个普通体型单位同时贴身攻击一个中型目标，狭窄区域默认 3 个，体型与能力可修正。

敌方采用带权行为树：候选行为、条件、目标和权重可由战斗 AI 编译，但选择使用本地固定 RNG，效果仍由规则引擎结算。100 个丧尸保留 100 个体账本，仅在计算、UI 和叙事上合批。

## 控制模式

- **纯手操**：服务器自动完成刷新、先攻及非玩家单位的普通行动；轮到受控单位时暂停，玩家选择路径、主要/次要动作、技能/物品、目标、资源上限和后备动作。队友与召唤物可逐个切换手动或 AI。
- **半自动**：自然语言策略先编译为可编辑规则并确认。任一接管条件满足即暂停：HP/EP 阈值、击杀比例、Boss 阶段、队友倒地、异常状态、资源耗尽、指定轮次、增援、新威胁、无合法动作或新脚本待批。
- **全自动**：本地策略持续推进到一方失能、撤退、投降、玩家濒死、安全停止或僵局。玩家 HP≤0 必停；最多 200 轮；连续 10 轮没有生命、资源、位置、状态、召唤或阶段变化判定僵局。

关键反应窗口会暂停；一般反应按已确认策略执行。正式暂停点和战斗结束时才调用一次正文 AI 生成融合叙事。

## 能力脚本沙箱

能力脚本在 QuickJS/WASM 中运行。禁用文件、网络、进程、环境变量、系统时钟、`Math.random`、`eval`、`Function`、动态导入和直接状态写入；只暴露只读快照、引擎 RNG 与声明式效果 API。单次 25ms、16MB、每动作最多 64 个效果、触发深度 8、源码 64KB。

首次使用必须显示来源、摘要、能力权限、可能效果和固定种子测试结果，由玩家确认；审批缓存键为规范化能力哈希 + 规则版本。内容或规则变化后重新审批。脚本异常冻结当前动作，不允许 AI 代算。

## API

- `POST /api/combat/sessions` 创建并本地校验遭遇
- `GET /api/combat/:id` 获取快照
- `GET /api/combat/:id/events?after=` 获取增量事件
- `GET /api/combat/:id/replay` 获取完整可复现记录
- `POST /api/combat/:id/strategy/compile` 编译并预览策略
- `POST /api/combat/:id/scripts/:hash/approve` 审批脚本
- `POST /api/combat/:id/start` 开战
- `POST /api/combat/:id/commands` 提交手动命令
- `POST /api/combat/:id/reactions` 提交反应
- `POST /api/combat/:id/advance` 半自动/全自动推进
- `POST /api/combat/:id/control` 变更单位控制权
- `POST /api/combat/:id/pause`、`resume`、`finalize`

## 极端场景验收

1. **主角 vs 100 丧尸**：个体状态正确；接触容量限制生效；范围伤害逐体结算；50 杀或 50% HP 可触发接管；单轮本地演算目标低于 500ms。
2. **主角 vs Boss**：Boss 独立；70/40/15% 阶段、预警、打断、部位和环境机制确定性触发；关键反应可暂停；濒死必停。
3. **主角 vs Boss + 小兵**：Boss 独立时间线，小兵 cohort；不存在共享血条或“人数等于攻击次数”；Boss 死亡后小兵重新评估，Boss 撤退不会删除小兵。
4. 覆盖同时失能、溢出伤害、1000 单位、一次范围击杀 80、无限召唤/触发、治疗僵局、目标抢先死亡、先攻同值、非法距离/资源、撤退追击、载具摧毁、形态解除、控制、友伤、刷新重放、幂等冲突、脚本越权、叙事冲突和战中规则升级。

## 完成标准

同一规则版本、输入与种子生成相同事件哈希；所有数值变化能追溯至动作、脚本、骰点和公式；AI 无法直接修改权威状态；三种模式和三类极端战场可完成；未经审批的脚本不能执行；叙事失败后战果仍可恢复；最终剧情楼层关联完整重放与 MVU 更新。
